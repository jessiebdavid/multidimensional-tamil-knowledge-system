# Integration Contract

## Purpose

This document defines the contract between the Scientific Intelligence branch and the Tamil RAG branch.

The contract ensures that both branches can be developed independently and integrated later without changing their internal implementations.

---

## 1. Scientific Query Input

The Scientific Intelligence branch may produce a structured query containing:

- Original user query
- Extracted scientific concepts
- Scientific domain
- Expanded scientific concepts
- Context information
- Requested dimensional analysis

The exact schema will be implemented in:

`shared/schemas/scientific_query.py`

---

## 2. Tamil Retrieval Request

The Scientific branch sends a structured retrieval request to the Tamil RAG branch.

The retrieval interface is defined in:

`shared/interfaces/tamil_retrieval.py`

The Tamil RAG branch is responsible for:

- Searching the Tamil corpus
- Retrieving relevant passages
- Calculating retrieval scores
- Returning source metadata
- Returning the retrieved Tamil text

---

## 3. Tamil Retrieval Result

The Tamil RAG branch returns structured retrieval results.

The schema is defined in:

`shared/schemas/tamil_retrieval.py`

A retrieval result may contain:

- Retrieved text
- Source identifier
- Source metadata
- Retrieval score
- Matched concepts

Retrieval score represents retrieval relevance only.

It must not be interpreted as relationship confidence.

---

## 4. Relationship Analysis

Relationship analysis occurs after scientific processing and Tamil retrieval.

The system evaluates whether a meaningful relationship exists between:

- Scientific concepts
- Tamil concepts
- Retrieved literary context
- Dimensional representations

Possible relationship classifications include:

- FACT
- INTERPRETATION
- ANALOGY
- HYPOTHESIS
- UNSUPPORTED

The system must be able to reject a proposed relationship.

It may return:

`No sufficiently relevant relationship was found.`

---

## 5. Relationship Confidence

Relationship confidence is generated by the relationship analysis stage.

It must remain separate from the Tamil RAG retrieval score.

Retrieval score:

`How relevant is the retrieved passage to the query?`

Relationship confidence:

`How strongly does the evidence support the identified relationship?`

---

## 6. Structured Analysis Result

The final structured analysis is represented by:

`shared/schemas/analysis_result.py`

It will contain the information required by the Final LLM synthesis stage.

The schema should support:

- Scientific concepts
- Tamil concepts
- Retrieved evidence
- Dimensional analysis
- Relationship classification
- Relationship confidence
- Supporting reasoning
- Limitations

---

## 7. Mock RAG Contract

Before the real Tamil RAG backend is available, a mock implementation may be used to test integration.

Mock records must be clearly marked as:

`SYNTHETIC_TEST_RECORD`

Mock records must never be presented as genuine Tamil literary evidence.

---

## 8. Ownership

### Scientific Intelligence Branch

Owns:

- Scientific knowledge base
- Scientific query processing
- Tiny/Small LLM
- Wormhole
- Scientific-to-Tamil concept bridge
- Dimensional routing
- Relationship analysis

### Tamil RAG Branch

Owns:

- Tamil corpus
- Tamil preprocessing
- Embeddings
- Vector database / FAISS
- Retrieval
- Reranking

### Shared

Both branches follow the contracts under:

`shared/schemas/`

`shared/interfaces/`

---

## 9. Integration Principle

Internal implementation details of either branch must not be required by the other branch.

Communication must occur through the shared schemas and interfaces.

This allows both branches to be developed independently and integrated later.
